Verification

How I check the numbers

Every number on the sites comes from tested code or a cited, dated source, and every model is checked against something independent of it: RTL, a real framework, an official SDK, PyTorch or a published figure.

The quotes below are copied from each site's About page, its README or its results.md, and a script checks that every quote still appears, word for word, on the page it links to.

Exact ports, with fixtures in CI

Each site's browser code is a TypeScript port of a Python reference. The reference writes JSON fixtures, and the site's unit tests require the port to reproduce them; for most sites exactly, with no tolerance. On GPU Kernels Explained, for example, “CI fails if the fixtures are out of date.” (source).

  • GPU Kernels Explained: “the unit tests require the port to reproduce all of them exactly, with no tolerance”. Source
  • Numerics Explained: “decodes every code of every format up to 16 bits and compares it with numpy (FP16) and ml_dtypes (BF16, FP8, FP6, FP4)”. Source
  • Inference Trade-offs Explained: “For every one of the 350 points, the vendored engine on the recorded workload reproduces the point's TTFT, TPOT and ITL percentiles exactly”. Source
  • LLM Inference Explained: “copied byte for byte from a pinned commit by a script that records the commit and the file’s SHA-256”. Source
  • Agent Evals Explained: “the TS port reproduces every fixture exactly, with no tolerance”. Source

Sourced specs, validation bands, and where the models miss

The hardware sites take every specification from a dated source and never use vendor claims as inputs. Their models are then checked against published figures that they do not take as inputs, and the misses are reported, not hidden.

  • AI Accelerators Explained: “The model is checked against 9 published figures it does not take as inputs” Source

The hardware decks

Signal Integrity. 20 of the series' results are cross-checked against independently published values (Cohn 1955, Hall & Heck, Johnson & Graham); the largest difference is 2.44 %. Its README lists every check, internal ones included (the table).

RTL challenges. Parsing is not simulating: “Nineteen challenges: six did not compile, eleven compiled but failed when first run”. Today: “All nineteen pass (nine in Verilator, ten in xsim)” (source).
