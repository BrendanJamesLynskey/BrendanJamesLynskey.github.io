# Brief: one landing page at brendan-lynskey.vercel.app (portfolio + CV + Digital Twin)

The owner wants one URL that is the landing page for their public sites, their CV and their **Digital Twin**, an AI
"talk to my career" agent built in Ed Donner's *Proficient AI Engineer* curriculum, which is not deployed yet.
The URL is reserved: the Vercel project `brendan-lynskey` (team `brendan-lynskeys-projects`) currently serves a
placeholder at https://brendan-lynskey.vercel.app. **Build on this repo** (the brief-40 portfolio home): do not
start a second front page. Work on a branch, open one PR, do not merge or deploy (the owner deploys).

Read first: `README.md`, `tools/build.py`, `tools/content.py`, `src/how-this-is-built.html`, and
`src/cv_source.md`.

## 0. Ground rules

- **Facts:** every CV claim comes from `src/cv_source.md`. Rewording and better structure are welcome; new facts,
  numbers, dates, awards or skills are not. Never publish a home address, phone number or email.
  - The existing home page keeps its rules: no location or contact details beyond GitHub on `/`, and nothing typed
    in that has a source.
  - The CV page may name employers and show "Leeds, UK" and LinkedIn.
- **Look:** the owner's usual CV is deliberately plain; this one may be **nicer**.
  - Make it well designed, typographically confident and easy to scan.
  - It must still read as written by a person: no buzzword soup, no "passionate", "leveraging", "cutting-edge" or
    "results-driven". Short concrete lines.
- **Same craft rules as the home page:** plain HTML/CSS generated by `tools/build.py`, system fonts, no external
  requests, light and dark (respecting the system setting), 16 px gutters and no horizontal scroll at 390 px, axe
  clean, Lighthouse ≥ 0.95 in every category.

## 1. The CV page: `/cv/`

- **Content source:** generate it from `src/cv_source.md`, via a small parser or a structured `tools/cv.py`
  derived from it. Add a check that every experience entry, date range, education item and award string in the
  source appears on the page and that nothing else in those categories does.
- **Top of the page:**
  - name, headline, "Leeds, UK", and links to LinkedIn, GitHub and the portfolio;
  - a **Download PDF** button.
- **Body sections:**
  - a short profile (3–4 lines);
  - a **career timeline graphic**: an SVG strip from 1994 to now with one band per role, coloured by domain
    (hardware / FPGA-SoC / DSP / software-AI), with role titles on hover or focus and a text alternative;
  - Experience;
  - **Selected public work**: 4–6 cards linking the strongest live sites and showcases, drawn from `data/` and
    `tools/content.py` (so the blurbs are not retyped), e.g. the HW design-space agent, the transformer decoder
    explainer and a hardware hub;
  - Skills, as compact grouped chips;
  - Education;
  - Certifications.
- **PDF:** `tools/cv_pdf.js` (puppeteer, `headless: "shell"`, A4, two pages maximum) prints `/cv/` with a print
  stylesheet to `cv/Brendan_Lynskey_CV.pdf`, committed. The print layout drops the timeline's interactivity and the
  theme, and keeps the links clickable.

## 2. Home page changes

- **New strip:** a "CV · Digital Twin · Contact" strip near the top of `/`, three cards:
  - **CV** → `/cv/` (with the PDF link);
  - **Digital Twin**: a **"coming soon" placeholder card**. It is generated from one constant in `tools/content.py`
    (`DIGITAL_TWIN = {"url": None, "label": ...}`), so the owner can switch it live later by setting the URL and
    rebuilding. Its text: a chat agent, trained on the owner's career, that answers questions about it, built in
    Ed Donner's Proficient AI Engineer curriculum. The card is disabled and labelled "coming soon" while the URL
    is None; it becomes a link when the URL is set;
  - **Contact** → LinkedIn.
- Add `/cv/` to the nav, the sitemap and the README.

## 3. One site, two addresses

- **Canonical:** set `BASE` (canonical, og:url, sitemap, robots) to `https://brendan-lynskey.vercel.app`, which is
  now the canonical address. GitHub Pages keeps serving the same files from `main`, so old links still work. Their
  canonical tags point to Vercel.
- **Vercel config:** add a minimal `vercel.json` for a static deploy with no build step (clean URLs, trailing slash
  consistent with GitHub Pages, 404 page). Make sure nothing private or tool-only is served: exclude `tools/`,
  `docs/`, `src/*.md` and `data/` via `.vercelignore`. GitHub Pages already serves them, which is acceptable
  because the repo is public.
- **Owner deploy script:** add `tools/deploy_vercel.sh`. It does a `git archive` of `origin/main` into a temporary
  directory and runs `vercel deploy --prod --yes --scope brendan-lynskeys-projects --project brendan-lynskey` (or
  a link first if that flag is unsupported), then curls the URL. The owner runs it.
- **Profile README:** update `tools/profile_readme.py` so the profile README links to the new URL. Do not push the
  profile repo; say in the PR what the owner must run.

## 4. Checks and done

Run all of the following on the branch and report them in the PR:

- `tools/check_quotes.py`, `tools/check_links.py`, and `tools/check_pages.js`, extended to `/cv/`;
- the new CV fact check;
- Lighthouse for `/` and `/cv/`;
- the page screenshots at 1280 and 390 px, light and dark, plus page 1 of the PDF, read by you.

Keep jobs light: 2 cores and 4 GB.

- what was built;
- every wording choice that strays furthest from `cv_source.md`, so the owner can check it;
- how to switch the Digital Twin card live;
- the owner's deploy command.

Do not merge or deploy.
